2.1 SCOPE — IN
────────────────────────────────────────────────────────────────────────────────

✅ Auth Endpoints (6 total — API_CONTRACT v1.2 §7):
   - POST /auth/register       — 10 req/hour per IP, X-Idempotency-Key required
   - POST /auth/login          — 5 req/min per IP
   - POST /auth/verify-otp     — 5 req/15min per IP
   - POST /auth/refresh-token  — 10 req/15min per user (via sub claim)
   - POST /auth/logout         — JWT required
   - GET  /users/me            — JWT required, RLS enforced

✅ JWT Infrastructure:
   - RS256 (asymmetric, RSA 2048-bit minimum)
   - access_token: 1 hour expiry
   - refresh_token: 7 days expiry (with rotation)
   - Claims: sub, email, role, tier, token_type, jti, iat, exp, iss
   - Refresh Token Rotation: old jti blacklisted in Redis

✅ Password Security:
   - bcrypt hashing (cost factor ≥ 12)
   - Password requirements: min 8, complexity (upper/lower/number/symbol)
   - Password_hash VARCHAR(255) in users table

✅ OTP Verification:
   - 6-digit code generation
   - Sent via Twilio (SMS) or SendGrid (Email)
   - TTL 5 minutes in Redis
   - Rate limit 5 req/15min per IP
   - NOTE: Verification state ephemeral (Redis-only) — sesuai DATABASE_SCHEMA 
     v2.9 yang TIDAK punya kolom is_email_verified/email_verified_at

✅ RBAC (Role-Based Access Control):
   - 4 roles: customer, event_organizer, gate_staff, admin
   - 3 enforcement layers: HTTP middleware, endpoint RBAC, RLS policies

✅ RLS Enforcement:
   - users table: users can view/update own data
   - Admin/EO can view all users (via JWT role claim)

✅ Refresh Token Blacklist:
   - Redis keyspace: refresh_blacklist:{jti}
   - TTL = remaining expiry time (min 1 second)
   - Dual check: JWT signature + Redis blacklist

JWT TOKEN GENERATION (RS256):

  func LoadPrivateKey() (*rsa.PrivateKey, error) {
    pemData := []byte(os.Getenv("JWT_PRIVATE_KEY"))
    block, _ := pem.Decode(pemData)
    return x509.ParsePKCS1PrivateKey(block.Bytes)
  }

  func LoadPublicKey() (*rsa.PublicKey, error) {
    pemData := []byte(os.Getenv("JWT_PUBLIC_KEY"))
    block, _ := pem.Decode(pemData)
    return x509.ParsePKIXPublicKey(block.Bytes)
  }

AUTH MIDDLEWARE (per TDD v1.10 §8):

  func AuthMiddleware(blacklist *TokenBlacklistService) gin.HandlerFunc {
    return func(c *gin.Context) {
      token := c.GetHeader("Authorization")
      if token == "" {
        c.JSON(401, ErrorResponse("UNAUTHORIZED"))
        c.Abort()
        return
      }

      claims, err := jwtService.ValidateAccessToken(token)
      if err != nil {
        c.JSON(401, ErrorResponse("UNAUTHORIZED"))
        c.Abort()
        return
      }

      if claims.TokenType != "access" {
        c.JSON(401, ErrorResponse("TOKEN_TYPE_MISMATCH"))
        c.Abort()
        return
      }

      blacklisted, _ := blacklist.redis.Get(ctx, "access_blacklist:"+claims.JTI).Result()
      if blacklisted == "1" {
        c.JSON(401, ErrorResponse("TOKEN_BLACKLISTED"))
        c.Abort()
        return
      }

      c.Set("user_id", claims.UserID)
      c.Set("role", claims.Role)
      c.Set("tier", claims.Tier)
      c.Next()
    }
  }

REFRESH TOKEN HANDLER (per TDD v1.10 §6.7):

  func (h *AuthHandler) RefreshToken(c *gin.Context) {
    var req RefreshTokenRequest
    if err := c.BindJSON(&req); err != nil {
      c.JSON(400, ErrorResponse("INVALID_REQUEST"))
      return
    }

    claims, err := h.jwtService.ParseRefreshToken(req.RefreshToken)
    if err != nil {
      c.JSON(401, ErrorResponse("UNAUTHORIZED"))
      return
    }

    if claims.TokenType != "refresh" {
      c.JSON(401, ErrorResponse("TOKEN_TYPE_MISMATCH"))
      return
    }

    blacklisted, _ := h.redis.Get(ctx, "refresh_blacklist:"+claims.JTI).Result()
    if blacklisted == "1" {
      c.JSON(401, ErrorResponse("TOKEN_BLACKLISTED"))
      return
    }

    user, err := h.repo.GetUserByID(ctx, claims.UserID)
    if err != nil || user.Status != "ACTIVE" {
      c.JSON(403, ErrorResponse("FORBIDDEN"))
      return
    }

    ttl := time.Until(time.Unix(claims.Exp, 0))
    if ttl <= 0 {
      ttl = 1 * time.Second
    }
    h.redis.Set(ctx, "refresh_blacklist:"+claims.JTI, "1", ttl)

    newAccessToken, _ := h.jwtService.GenerateAccessToken(user)
    newRefreshToken, _ := h.jwtService.GenerateRefreshToken(user)

    c.JSON(200, gin.H{
      "data": gin.H{
        "access_token":  newAccessToken,
        "refresh_token": newRefreshToken,
        "expires_in":    3600,
      },
    })
  }

LOYALTY TIER COMPUTATION (untuk GET /users/me):

  Dari DATABASE_SCHEMA Query 4 (Performance Optimization):

    SELECT
      id, name, total_purchases, base_score,
      CASE
        WHEN (base_score + total_purchases * 10) >= 90 THEN 'TIER_1'
        WHEN (base_score + total_purchases * 10) >= 70 THEN 'TIER_2'
        ELSE 'TIER_3'
      END as fan_tier
    FROM users
    WHERE role = 'customer'
    ORDER BY (base_score + total_purchases * 10) DESC;

  → loyalty_score = base_score + total_purchases * 10
  → loyalty_tier = TIER_1 (>=90), TIER_2 (70-89), TIER_3 (<70)

3.4 FROM SECURITY_SPEC v1.4 §2 — AUTH SECURITY
────────────────────────────────────────────────────────────────────────────────

PASSWORD HASHING:
  - Algorithm: bcrypt (cost factor ≥ 12)
  - Stored in users.password_hash (VARCHAR 255)
  - Never transmitted over HTTP (HTTPS only)

PASSWORD REQUIREMENTS:
  - Minimum: 8 characters
  - Complexity: Mix of upper, lower, numbers, symbols
  - Max: 128 characters (bcrypt truncates at 72, so limit input)
  - No common patterns (123456, password, etc.)

HEADER SANITIZATION (Logger):
  - Authorization: Bearer <token> → Authorization: Bearer [REDACTED]
  - X-Admin-2FA-Token → [REDACTED]
  - X-Queue-Token → [REDACTED]

PII MASKING:
  - Never log: password_hash, full tokens, full email/phone
  - Log masked: phone (****5678), email (b***@example.com) untuk error tracking

TOKEN STORAGE (PWA — for frontend reference):
  - access_token: In-memory (cleared on browser close) or sessionStorage
  - refresh_token: HttpOnly cookie (immune to XSS)
  - NEVER localStorage (XSS vulnerable)
  - Service Worker cache: NO tokens cached

THREAT MAPPING untuk FASE 1:

| Threat                    | Mitigation                                          |
|---------------------------|-----------------------------------------------------|
| Credential Theft          | bcrypt cost=12, HTTPS-only, password complexity     |
| Account Compromise        | JWT RS256 + Refresh Rotation + jti blacklist        |
| Brute Force Login         | Rate limit 5 req/min per IP                         |
| OTP Brute Force           | Rate limit 5 req/15min per IP + 6-digit OTP TTL 5m  |
| Session Hijacking         | Short access token expiry (1h) + refresh rotation   |
| Replay Attack (refresh)   | Old jti blacklisted in Redis (SET with TTL)         |
| Token Type Confusion      | Explicit token_type claim check (access vs refresh) |
| IDOR / BOLA               | RLS enforced (users can view own data only)         |
| XSS Token Theft           | Refresh token HttpOnly cookie (frontend)            |
| User Enumeration          | Generic error messages (no "email not found")       |

SECTION 7 — RISKS & MITIGATIONS
================================================================================

| Risk                                              | Likelihood | Impact | Mitigation                                          |
|---------------------------------------------------|------------|--------|-----------------------------------------------------|
| JWT key mismatch (private/public) saat startup    | Medium     | High   | Load both keys di init, fail-fast kalau mismatch    |
| bcrypt cost terlalu tinggi → slow login           | Low        | Med    | Cost=12 (balance); benchmark sebelum finalize       |
| Refresh rotation race condition (2 concurrent)    | Medium     | High   | Redis SET NX untuk blacklist (atomic)               |
| OTP spam (user minta berkali-kali)                | High       | Low    | Rate limit 5 req/15min + TTL 5 min                  |
| User enumeration (register 409 vs 400)            | Medium     | Med    | Return same generic error untuk security           |
| Token di-log secara tidak sengaja                 | Medium     | High   | Header sanitization middleware + unit test          |
| RLS policy salah → data leak                      | Low        | Critical| Integration test verify RLS enforced                |
| Suspended user masih bisa login (status check)    | Medium     | High   | Explicit check status='ACTIVE' + test case          |
| Bcrypt password truncation (72 char limit)        | Low        | Low    | Max input validation 128 char (bukan 72)             |
| Refresh-token rate limit identify user gagal      | Medium     | Low    | Fallback IP-based jika sub claim tidak bisa di-extract |

RESPONSE PER SCENARIO (cross-reference DRP v1.2):

- JWT key compromise → Playbook #6 (DRP v1.2 §5.7) — rotate keys, blacklist all tokens
- Redis down (blacklist unavailable) → Playbook #2 (DRP v1.2 §5.3) — Circuit Breaker, 
  temporarily fail-open untuk refresh (dengan warning), fail-closed untuk access
- DB down → Playbook #1 (DRP v1.2 §5.2)

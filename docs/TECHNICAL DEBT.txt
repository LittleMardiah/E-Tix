# TECHNICAL DEBT - E-Tix Flash

## Tujuan

Dokumen ini adalah register hutang teknis (technical debt) proyek E-Tix Flash.
Setiap utang teknis yang ditemukan dan masih perlu dibereskan dicatat di sini
sebagai entry dengan ID sendiri, supaya tidak hilang dan bisa dilacak sampai selesai.

Dokumen ini berbeda dari docs/PORTFOLIO IDEAS.txt.
PORTFOLIO IDEAS.txt berisi ide-ide tambahan untuk nilai jual portofolio.
TECHNICAL DEBT.txt berisi masalah teknis nyata yang perlu diperbaiki.

## Konvensi ID

Format: TD-001, TD-002, TD-003, dan seterusnya.
Nomor tiga digit, urut, tidak pernah dipakai ulang.
Satu entry satu ID, tidak digabung.

## Status Bucket

Setiap entry hanya boleh punya satu status dari daftar berikut.

- OPEN. Utang teknis ditemukan, belum ada yang mengerjakan.
- IN PROGRESS. Sedang diperbaiki.
- FIXED. Sudah diperbaiki, sudah diverifikasi, belum ditutup secara resmi.
- CLOSED. Sudah selesai dan sudah dikonfirmasi selesai.
- DEFERRED. Sengaja ditunda, alasannya dicatat di Deskripsi.

## Template Entry

Salin blok di bawah setiap kali menambah entry baru.
Isi semua bagian. Jangan biarkan bagian kosong.

ID: TD-00X
Tanggal: YYYY-MM-DD
Status: OPEN | IN PROGRESS | FIXED | CLOSED | DEFERRED
Prioritas: TINGGI | SEDANG | RENDAH
Deskripsi: Gejala yang terlihat dan dampaknya ke pengguna atau sistem.
Root Cause: Penyebab sebenarnya kenapa hal ini terjadi.
Rencana Fix: Langkah kerja konkret untuk membereskannya, plus file yang akan disentuh.
Referensi: File, baris, dokumen, atau issue tempat masalah ini ditemukan.

## Contoh Entry Terisi

Contoh berikut hanya ilustrasi format, bukan utang teknis yang nyata.
Jangan dihitung sebagai entry aktif.

ID: TD-000
Tanggal: YYYY-MM-DD
Status: OPEN
Prioritas: TINGGI
Deskripsi: Contoh isi deskripsi masalah.
Root Cause: Contoh isi akar penyebab.
Rencana Fix: Contoh langkah perbaikan.
Referensi: docs/CONTOH.txt

ID: TD-001
Tanggal: 2026-10-02
Status: ✅ FIXED
Fixed in: commit 2e2b9b6 (2026-10-14)
Prioritas: RENDAH
Deskripsi: Belum ada .editorconfig di root repo. .gitattributes sudah
men kunci line ending lewat git, tapi editor di Windows tetap bisa
menulis CRLF ke disk setelah file di checkout. Karena atribut text
membuat git menormalkan CRLF jadi LF saat add, status git tetap
bersih padahal isi file di disk sudah beda byte dari isi commit.
Akibatnya diff yang terlihat di editor tidak selalu sama dengan
apa yang benar-benar tersimpan di git.
Root Cause: .gitattributes hanya berlaku saat git membaca atau
menulis file, tidak berlaku saat editor menulis file. Tidak ada
aturan sisi editor yang memaksa LF, jadi konfigurasi editor pada
Windows bisa menimpa file dengan CRLF tanpa handler git menyadarinya.
Rencana Fix: tambah .editorconfig di root repo dengan aturan
end_of_line lf untuk semua file, plus insert_final_newline true
dan trim_trailing_whitespace true. Bisa dikerjakan di FASE 0
bersama setup konfigurasi editor atau di FASE 9 tahap polish.
Referensi: Sesi 2c, kritik OpenCode.

ID: TD-F4-03
Tanggal: 2026-10-15
Status: ⏸️ DEFERRED
Prioritas: MEDIUM
Deskripsi: Graceful shutdown untuk worker goroutines. Saat ini 3 worker
  (fanScore, bookingExpiry, reconciliation) dijalankan dengan
  `context.Background()` di main.go. Tidak ada signal handler (SIGTERM /
  SIGINT) → worker mid-tx mati saat Render restart.
Root Cause: Wiring pakai hardcoded context.Background(), bukan root ctx.
Rencana Fix: signal.NotifyContext(context.Background(), os.Interrupt,
  syscall.SIGTERM) → pass ke semua worker.Run(ctx). Drain dengan 30s timeout
  sebelum router shutdown.
Referensi: docs/AUDIT FASE 4.md §4, opencode review 2026-10-15.

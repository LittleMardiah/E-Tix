3.1 FROM PRD v6.0 §F001 — BEHAVIORAL INGRESS SPEC (FULL)
────────────────────────────────────────────────────────────────────────────────

DESCRIPTION:
  Menangani ingress traffic saat flash sale dengan memisahkan beban kerja 
  menjadi dua tahap (synchronous cepat + asynchronous mendalam) untuk menjaga 
  latency tetap rendah. Menggunakan pre-computed base score untuk menghindari 
  cold-start pada request pertama pengguna. Memberikan akses prioritas kepada 
  fans loyal.

INPUTS:
  - User ID (UUID string)
  - Device Fingerprint (encrypted string) — optional
  - Access Metadata (request interval, IP, TLS parameters)

PROCESS — Pra-Flash Sale:
  NOTE (FASE 2 interpretasi): "Pre-computation" di-skip untuk MVP. Base Score 
  dibaca on-demand dari users.base_score (default 50). 

  Base Score Formula (untuk future reference — FASE 8):
    - Umur akun: (NOW() - created_at) / 365 hari → +10 poin per tahun
    - Email terverifikasi → +10 poin
    - Phone terverifikasi → +10 poin
    - Total purchases >= 1 → +10 poin
    - Total purchases >= 3 → +30 poin
    - Total purchases >= 5 → +50 poin
    (Clamp 0-100)

PROCESS — Stage 1 (Synchronous, Target < 1ms):
  1. Rate Limiter cek limit per IP/User ID.
  2. Validasi header dasar (User-Agent, Accept-Language).
  3. Cek blacklist IP di memory cache (update dari Redis setiap 60s).
  4. Baca Base Score dari Redis (fallback: DB users.base_score).
  5. Baca Dynamic Score dari Redis (jika ada dari request sebelumnya).
  6. Hitung Final Score = Base + Dynamic.
  7. Tentukan Tier:
       - > 90 → Tier 1 (Priority)
       - 70-90 → Tier 2 (Normal)
       - < 70 → Tier 3 (Low Priority)
  8. Kirim metadata ke Message Broker (RabbitMQ fan_score queue) untuk Stage 2.
  9. Generate Queue Token (JWT) dengan payload: 
     { user_id, tier, final_score, jti, exp: NOW() + 5 min }

PROCESS — Stage 2 (Asynchronous, Background Worker):
  1. Worker menerima metadata dari queue.
  2. Hitung Dynamic Score berdasarkan perilaku real-time:
     - Interval antar request (terlalu cepat → minus)
     - Pola klik (manusia vs bot)
     - Device fingerprint (known bot pattern)
  3. Update Final Score = Base + Dynamic.
  4. Simpan di Redis: user:score:{user_id}:dynamic dengan TTL.
  5. Jika Final Score < 50 → kirim notifikasi ke Admin + CAPTCHA trigger.
  6. Jika terdeteksi pola bot yang jelas → tambahkan ke blacklist.

OUTPUTS:
  - Signed Queue Token (JWT dengan payload expiry & priority tier)
  - Error Response / HTTP 429 Too Many Requests
  - Waiting Room dengan visualisasi tier

EDGE CASES:
  - Traffic Spike Extreme (>50,000 RPS) → Circuit Breaker + Virtual Waiting 
    Room via WebSocket Cluster (FASE 9 hardening)
  - User baru tanpa Base Score → default 50 + pantau Stage 2
  - Cache Cluster Failure → Degraded Mode (Circuit Breaker fallback)
  - Fans setia yang terlambat masuk waiting room → tetap prioritas

2-STAGE PIPELINE (F001):

  Stage 1 (Synchronous — <1ms):
    - Rate Limiter (Token Bucket) per IP/User ID
    - Header validation (User-Agent, Accept-Language)

      * Click patterns (human vs bot)

    - Final Score = Base Score + Dynamic Score
    - If Final Score < 50 → CAPTCHA trigger + alert admin
    - If bot pattern detected → add to blacklist

FAN SCORE TIERS:

  | Tier   | Score Range | Priority Access               |
  |--------|-------------|-------------------------------|
  | TIER_1 | > 90        | VIP — First in queue          |
  | TIER_2 | 70-90       | Regular — Normal access       |
  | TIER_3 | < 70        | Low priority / CAPTCHA        |

QUEUE TOKEN LIFECYCLE:

  1. Issued: POST /queue/verify-captcha OR GET /queue/status
  2. Payload:
     {
       "user_id": "uuid",
       "tier": "TIER_2",
       "final_score": 85,
       "jti": "uuid-jti-123",
       "exp": 1723641300,  // 5 minutes
       "iss": "e-tix-flash-queue"
     }
  3. Single-Use Guard:
     - On use: SET queue_token:used:{jti} 1 NX EX 300
     - If return nil (already exists) → HTTP 409 TOKEN_ALREADY_USED

     Header: X-Queue-Token: <jwt-queue-token>

CAPTCHA MODAL TRIGGER CONDITIONS:
  - Final Score < 50
  - Multiple failed booking attempts in short time
  - Suspicious device fingerprint

CAPTCHA FLOW:
  1. Client detects challenge required → shows CAPTCHA modal
  2. User solves challenge (client-side)
  3. POST /queue/verify-captcha
     Body: { "challenge_id": "uuid", "solution": "traffic_lights" }
  4. Backend validates:
     - Solution correct? (server-side verify ke provider API)
     - Not expired?
     - Attempts < 3?
  5. If valid → return queue_token (JWT with jti)
  6. If invalid → increment failed attempts
     - 3 failures → 15 min lockout (Redis)

3.8 FROM TDD v1.10 §6.1 — STAGE 1/STAGE 2 GO IMPLEMENTATION

STAGE 1 (Synchronous — Target < 1ms):

  func (m *IngressMiddleware) Handle(c *gin.Context) {
    userID := c.GetString("user_id")  // dari FASE 1 AuthMiddleware
    ip := c.ClientIP()

    // Rate Limiter (Token Bucket)
    if !m.rateLimiter.Allow(ip, "ingress", 100, time.Minute) {
      c.JSON(429, ErrorResponse("RATE_LIMIT_EXCEEDED"))
      c.Abort()
      return
    }

    // Blacklist check (memory cache, updated from Redis every 60s)
    if m.blacklist.IsBlacklisted(ip) {
      c.JSON(403, ErrorResponse("BLACKLISTED"))
      c.Abort()
      return
    }

    // Base Score from Redis (fallback: DB)
    baseScore, _ := m.redis.Get(ctx, "user:score:"+userID+":base").Int()
    if baseScore == 0 {
      user, err := m.userRepo.GetUserByID(ctx, userID)
      if err != nil {
        c.JSON(404, ErrorResponse("USER_NOT_FOUND"))
        c.Abort()
        return
      }
      baseScore = user.BaseScore
      m.redis.Set(ctx, "user:score:"+userID+":base", baseScore, 24*time.Hour)
    }

    // Dynamic Score from Redis
    dynamicScore, _ := m.redis.Get(ctx, "user:score:"+userID+":dynamic").Int()

    finalScore := baseScore + dynamicScore

    // Priority Tier
    var tier string
    switch {
    case finalScore > 90:
      tier = "TIER_1"
    case finalScore >= 70:
      tier = "TIER_2"
    default:
      tier = "TIER_3"
    }

    // Generate Queue Token (JWT with jti)
    token := generateQueueToken(userID, tier, finalScore)

    // Async: send to Stage 2 worker
    m.queue.Publish("fan_score", metadata{userID, ip, finalScore, time.Now()})

    c.Set("queue_token", token)
    c.Set("tier", tier)
    c.Set("final_score", finalScore)
    c.Next()
  }

STAGE 2 (Asynchronous — Background Worker):

  func (w *FanScoreWorker) Process(ctx context.Context, msg []byte) {
    var meta Metadata
    if err := json.Unmarshal(msg, &meta); err != nil {
      w.logger.Error("invalid fan_score payload", zap.Error(err))
      return
    }

    // Calculate dynamic score based on behavior
    dynamicScore := calculateDynamicScore(meta.IP, meta.UserID, meta.RequestInterval)

    // Update Redis
    w.redis.Set(ctx, "user:score:"+meta.UserID+":dynamic", dynamicScore, 24*time.Hour)

    // If score < 50, trigger CAPTCHA and alert admin
    if dynamicScore < 50 {
      w.alertService.NotifyAdmin("Low dynamic score", meta.UserID, meta.IP)
    }

    // Bot pattern detection → blacklist (via SYSTEM_USER_UUID)
    if isBotPattern(meta) {
      w.repo.InsertBlacklist(ctx, model.SystemUserUUID, "ip", meta.IP, "BOT_DETECTED", nil)
    }
  }

3.3 FROM LOGIC_FLOW v1.4 §8 — FLOW SUMMARY (PSEUDOCODE ONLY)
────────────────────────────────────────────────────────────────────────────────

BULK CANCELLATION FLOW:

  Function BulkCancel(ctx, eventID, reason):
    Step 1: Auth middleware (admin OR event_organizer)
    Step 2: Admin2FAMiddleware (verify X-Admin-2FA-Token)
    Step 3: Validate event exists
    Step 4: Count tickets + refund amount (preview):
              - SELECT COUNT(*) FROM tickets WHERE event_id = X
                AND status IN ('CONFIRMED', 'LOCKED', 'PENDING_SPLIT_PAY', 
                               'RESALE_PENDING')
              - Compute refund_total = SUM(payment_obligations.amount 
                WHERE status = 'PAID' AND booking.event_id = X)
    Step 5: INSERT admin_actions:
              action_type = 'BULK_CANCEL',
              target_resource_type = 'event',
              target_resource_id = eventID,
              reason = reason,
              changes_before = { event_status: ..., total_tickets: N }
    Step 6: Enqueue bulk_cancel job to MQ (async)
    Step 7: Return 202 Accepted:
              {
                event_id, cancelled_tickets: N, refund_total: "X",
                status: "PROCESSING"
              }

  BulkCancelWorker (async):
    Step 1: Consume job
    Step 2: BEGIN tx
    Step 3: SELECT tickets FOR UPDATE WHERE event_id = X
            AND status IN ('CONFIRMED', 'LOCKED', 'PENDING_SPLIT_PAY', 
                           'RESALE_PENDING')
    Step 4: UPDATE tickets SET status = 'CANCELLED'
    Step 5: SELECT payment_obligations WHERE status = 'PAID' 
            AND booking.event_id = X
    Step 6: FOR EACH obligation:
              a. Call PaymentGateway.Refund(external_transaction_id, amount)
              b. Retry 3x exponential backoff
              c. Success → UPDATE obligation status = 'REFUNDED'
              d. Fail → log PENDING_REFUND for admin followup
    Step 7: Release Redis bitmask per seat (granular SETBIT 0)
    Step 8: COMMIT
    Step 9: Publish user notification via RabbitMQ (ASYNC — FLAG #3):
              - Publish to notification_queue: { users: [...], 
                                                  template: 'BULK_CANCEL', 
                                                  event_name: ... }
              - NotificationWorker consumes → FCM/Email/SMS
              - Worker TIDAK blocking (fire-and-forget)
    Step 10: INSERT admin_actions (status update: PROCESSING → COMPLETED)

MANUAL REVERSE FLOW (Refund):

  Function ManualReverse(ctx, txID, reason):
    Step 1: Auth middleware (admin)
    Step 2: Admin2FAMiddleware
    Step 3: SELECT payment_obligation WHERE id = txID
              - If not found → 404
              - If status != 'PAID' → 409 (already refunded/not paid)
    Step 4: Call PaymentGateway.Refund(external_transaction_id, amount)
    Step 5: UPDATE payment_obligations SET status='REFUNDED', 
            refunded_at=NOW(), refund_transaction_id=gateway_refund_id
    Step 6: Trigger handle_ticket_cancellation_on_refund fires 
            → tickets.status = 'CANCELLED'
    Step 7: INSERT admin_actions:
              action_type = 'MANUAL_REFUND',
              target_resource_type = 'payment_obligation',
              target_resource_id = txID,
              reason = reason,
              changes_before = { status: 'PAID' },
              changes_after = { status: 'REFUNDED' }
    Step 8: Return 200:
              { payment_obligation_id, status: 'REFUNDED', 
                gateway_refund_transaction_id, admin_action_id, refunded_at }

LEDGER VIEW FLOW (FLAG #3):

  Function GetLedger(ctx, filters):
    Step 1: Auth (admin)
    Step 2: Parse filters (date_from, date_to, status, page, limit)
    Step 3: Limit validation: max 100
    Step 4: Query UNION ALL:
              (SELECT 
                 po.id as event_id,
                 CASE 
                   WHEN po.status='PAID' THEN 'PAYMENT_PAID'
                   WHEN po.status='PENDING' THEN 'PAYMENT_PENDING'
                   WHEN po.status='REFUNDED' THEN 'PAYMENT_REFUNDED'
                   ELSE 'PAYMENT_' || po.status
                 END as event_type,
                 'payment_obligation' as reference_type,
                 po.id as reference_id,
                 po.booking_id,
                 po.user_id,
                 po.amount,
                 po.status,
                 po.external_transaction_id as gateway_transaction_id,
                 po.created_at
               FROM payment_obligations po
               WHERE po.created_at BETWEEN date_from AND date_to)
              UNION ALL
              (SELECT 
                 rt.id, 'RESALE_COMPLETED' as event_type,
                 'resale_transaction' as reference_type, rt.id, ...,
                 rt.seller_payout as amount, rt.status, ..., rt.created_at
               FROM resale_transactions rt
               WHERE ...)
              UNION ALL
              (SELECT 
                 aa.id, 
                 CASE aa.action_type 
                   WHEN 'MANUAL_REFUND' THEN 'ADMIN_MANUAL_REFUND'
                   WHEN 'BULK_CANCEL' THEN 'ADMIN_BULK_CANCEL'
                   ELSE 'ADMIN_' || aa.action_type
                 END as event_type,
                 'admin_action' as reference_type, aa.id, ..., 
                 aa.amount_from_changes as amount, ...
               FROM admin_actions aa
               WHERE aa.action_type IN ('MANUAL_REFUND', 'MANUAL_PAID', 
                                       'BULK_CANCEL'))
              ORDER BY created_at DESC
              LIMIT $limit OFFSET $offset
    Step 5: Compute summary:
              total_paid = SUM(amount) WHERE event_type LIKE 'PAYMENT_PAID%'
              total_pending = SUM(amount) WHERE event_type = 'PAYMENT_PENDING'
              total_refunded = SUM(amount) WHERE event_type LIKE '%REFUNDED%'
              unreconciled_count = COUNT(*) WHERE status = 'PENDING' 
                                    AND created_at < NOW() - INTERVAL '15 min'
    Step 6: Return paginated response

FORCE RELEASE FLOW:

  Function ForceRelease(ctx, bookingID, reason):
    Step 1: Auth (admin)
    Step 2: Admin2FAMiddleware
    Step 3: SELECT booking FOR UPDATE
              - If not found → 404

    Step 8: COMMIT
    Step 9: Return 200

3.4 FROM TDD v1.10 §6.7 — ADMIN 2FA IMPLEMENTATION (FLAG #1)
────────────────────────────────────────────────────────────────────────────────

ADMIN 2FA MIDDLEWARE:

  Function Admin2FAMiddleware():
    Step 1: Extract X-Admin-2FA-Token dari header
              - If missing → 401 UNAUTHORIZED (or 401 ADMIN_2FA_REQUIRED)
    Step 2: Get admin_user_id dari context (set by AuthMiddleware)
    Step 3: Check lockout:
              - redis EXISTS admin_2fa_lockout:{user_id}
              - If exists → 429 (locked, return remaining TTL)
    Step 4: Get TOTP secret dari Redis:
              - secret = GET admin_2fa:{user_id}
              - If not found → 422 ADMIN_2FA_NOT_ENROLLED
    Step 5: Verify TOTP:
              - valid = totp.Validate(token, secret)
              - If !valid:
                  * INCR admin_2fa_fails:{user_id} with TTL 900
                  * If fails >= 3:
                      - SET admin_2fa_lockout:{user_id} 1 EX 900
                      - Log CRITICAL alert
                  * return 401 INVALID_2FA_TOKEN
    Step 6: Reset fails counter:
              - DEL admin_2fa_fails:{user_id}
    Step 7: c.Next()

TOTP ENROLLMENT (CLI SCRIPT):

  Function EnrollAdmin2FA(userID):
    Step 1: Generate TOTP secret (pquerna/otp)
    Step 2: Generate QR code untuk Google Auth/Authy
    Step 3: STORE secret di Redis: SET admin_2fa:{user_id} {secret}
              (PERSISTENT — no TTL, atau TTL indefinite)
    Step 4: Display QR + secret (one-time display)
    Step 5: Admin scan QR code → Google Auth/Authy
    Step 6: Verify enrollment: admin input 6-digit token → validate

  Note: Enrollment is OUT OF API SCOPE (CLI/provisioning script only).
  Tidak ada POST /admin/2fa/enroll endpoint.

BULK CANCEL HANDLER:

    Step 1: Auth + RBAC (admin OR event_organizer)

    Step 3: Validate event exists

  BulkCancelWorker:

8.4 BULK CANCEL SCOPE (FLAG #2)
────────────────────────────────────────────────────────────────────────────────

  Scope: status IN ('CONFIRMED', 'LOCKED', 'PENDING_SPLIT_PAY', 'RESALE_PENDING')
  Skip: 'USED', 'RESOLD', 'CANCELLED'

  Reasoning:
    - USED: sudah di-scan gate (refund tidak applicable)
    - RESOLD: sudah pindah tangan (new owner terpisah)
    - CANCELLED: sudah cancelled

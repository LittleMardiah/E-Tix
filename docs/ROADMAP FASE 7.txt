✅ Reservation Timeout (ResaleExpiryWorker):
   - Delayed message resale_expiry_check (TTL 3 min)
   - Lazy-check: query reserved rows WHERE status='PENDING' 
     AND buyer_user_id IS NOT NULL AND reservation_expires_at < NOW()
   - Atomic reset: buyer_user_id = NULL, reservation_expires_at = NULL
   - Log ke admin_actions (action_type = 'FORCE_RELEASE_SEAT', reason =

✅ Database Trigger handle_resale_lifecycle:
   - INSERT (status PENDING) → tickets.status = 'RESALE_PENDING'
   - UPDATE to COMPLETED → old ticket RESOLD + new ticket untuk buyer 
     (CONFIRMED, is_assigned=TRUE, original_owner_user_id=seller)

✅ Partial UNIQUE Index (schema constraint):

3.1 FROM PRD v6.0 §F005 — CONTROLLED RESALE SPEC
────────────────────────────────────────────────────────────────────────────────

DESCRIPTION:
  Memungkinkan pemegang tiket menjual kembali di platform resmi dengan 
  price-cap, menggunakan Payment Gateway sebagai mediator (tanpa wallet/ledger 
  internal).

INPUTS: Ticket ID, Seller User ID, Resale Price (max +10% face value), 
        Buyer User ID

PROCESS:
  1. Validasi tiket aktif dan belum dipindahtangankan
  2. Kunci tiket sementara (status RESALE_PENDING) cegah double-selling
  3. Payment via Payment Gateway (VA/E-Wallet/Kartu)
  4. Payout ke Seller via Payout API
  5. Transfer Ownership: QR lama invalidate, generate QR baru untuk buyer
  6. Pencatatan riwayat transaksi untuk audit

ATURAN KEPEMILIKAN:
  - Hanya pemilik tiket yang bisa jual
  - Untuk Bulk Mode yang sudah di-assign → anggota adalah pemilik sah
  - Untuk Bulk Mode yang belum di-assign → hanya Leader

OUTPUTS: New Ticket Ownership, Resale Receipt, Updated QR Code

EDGE CASES:
  - Seller cancel sebelum buyer bayar → lepas lock, status ACTIVE
  - Buyer gagal bayar → lepas lock (no refund — belum ada dana)
  - Price melebihi cap → 422
  - Payout API gagal → retry exponential backoff (3x), jika gagal → 
    status PENDING_PAYOUT + admin manual reconciliation (FASE 8)

3.2 FROM DATABASE_SCHEMA v2.9 — RESALE_TRANSACTIONS + TICKETS
────────────────────────────────────────────────────────────────────────────────

ENUMs (relevan):

  resale_status_enum   : PENDING | COMPLETED | CANCELLED | PENDING_PAYOUT
                         (⚠️ NO 'RESERVED' — FLAG #1)

  ticket_status_enum   : AVAILABLE | LOCKED | PENDING_SPLIT_PAY | CONFIRMED |
                         RESALE_PENDING | RESOLD | CANCELLED | USED

RESALE_TRANSACTIONS TABLE (full kolom):

  - id UUID (PK)
  - ticket_id UUID (FK tickets)
  - event_id UUID (FK events)
  - seller_user_id UUID (FK users)
  - buyer_user_id UUID (FK users, NULLABLE — NULL = belum di-klaim)
  - original_price NUMERIC(15,2) NOT NULL
  - resale_price NUMERIC(15,2) NOT NULL      → CONSTRAINT resale_price > 0
  - platform_fee NUMERIC(15,2) DEFAULT 0
  - seller_payout NUMERIC(15,2) NOT NULL
  - status resale_status_enum DEFAULT 'PENDING'
  - payment_transaction_id VARCHAR(255) (nullable)
  - payout_transaction_id VARCHAR(255) (nullable)
  - created_at TIMESTAMPTZ DEFAULT NOW()
  - completed_at TIMESTAMPTZ (nullable)
  - cancelled_at TIMESTAMPTZ (nullable)

  ⚠️ NOTE: TIDAK ADA kolom `reservation_expires_at` di schema!
  FLAG #1 RESOLUTION: Karena RESERVED tidak ada di enum + tidak ada kolom 
  reservation_expires_at, kita pakai APPROACH:
    - Status tetap 'PENDING' saat reserved
    - Reserved distinguished via: buyer_user_id IS NOT NULL
    - TTL track via delayed message RabbitMQ (bukan DB column)
    - ResaleExpiryWorker cek: WHERE status='PENDING' AND buyer_user_id 
      IS NOT NULL AND created_at < NOW() - INTERVAL '3 minutes'

  Constraints:
    - resale_price <= original_price * 1.10 (price cap)
    - seller_user_id != buyer_user_id (when buyer exists)
    - CHECK resale_price > 0

  Indexes:
    - idx_resale_ticket, idx_resale_seller, idx_resale_buyer, 
      idx_resale_status, idx_resale_event, idx_resale_event_status
    - PARTIAL UNIQUE: idx_resale_single_active ON ticket_id 
      WHERE status = 'PENDING'

TICKETS TABLE (relevant untuk trigger):

  - id, booking_id, payment_obligation_id, owner_user_id
  - section_id, seat_position, status (ticket_status_enum)
  - is_assigned, qr_secret_key, fallback_pin
  - original_owner_user_id (nullable), resale_transaction_id (nullable)
  - created_at, updated_at

  Partial UNIQUE: (booking_id, seat_position) WHERE status NOT IN 
                  ('RESOLD', 'CANCELLED')

TRIGGER handle_resale_lifecycle (AFTER INSERT OR UPDATE ON resale_transactions):

  THREE CASES:
  [CASE 1: INSERT]
    - UPDATE tickets SET status = 'RESALE_PENDING', updated_at = NOW()
      WHERE id = NEW.ticket_id

  [CASE 2: UPDATE to COMPLETED]
    - Get old_ticket_record FROM tickets WHERE id = NEW.ticket_id
    - Step 1: UPDATE old ticket:
        status = 'RESOLD',
        original_owner_user_id = OLD.seller_user_id,
        resale_transaction_id = NEW.id,
        updated_at = NOW()
    - Step 2: INSERT new ticket for buyer:
        booking_id = old_ticket_record.booking_id,
        payment_obligation_id = old_ticket_record.payment_obligation_id,
        owner_user_id = NEW.buyer_user_id,
        section_id = old_ticket_record.section_id,
        seat_position = old_ticket_record.seat_position,
        status = 'CONFIRMED',
        is_assigned = TRUE,
        qr_secret_key = gen_random_uuid(),
        fallback_pin = UPPER(SUBSTRING(REPLACE(gen_random_uuid(), '-', ''), 1, 12)),
        original_owner_user_id = OLD.seller_user_id,
        resale_transaction_id = NEW.id

  [CASE 3: UPDATE to CANCELLED]
    - UPDATE tickets SET 
        status = 'CONFIRMED',
        resale_transaction_id = NULL,
        updated_at = NOW()
      WHERE id = NEW.ticket_id

RLS POLICIES (resale_transactions):

  - "Users can view own resale transactions" → 
    SELECT if seller_user_id = auth.uid() OR buyer_user_id = auth.uid()
  - "Anyone can view pending resale tickets" → 
    SELECT if status = 'PENDING'
  - "Buyer can complete resale purchase" → 
    UPDATE if (seller_user_id = auth.uid() AND status = 'PENDING') OR
              ((buyer_user_id IS NULL OR buyer_user_id = auth.uid()) 
               AND status = 'PENDING')
    WITH CHECK status IN ('PENDING', 'COMPLETED', 'CANCELLED')
  - "Users can insert resale" → 
    INSERT WITH CHECK seller_user_id = auth.uid() AND 
    EXISTS (SELECT 1 FROM tickets WHERE id = ticket_id 
            AND owner_user_id = auth.uid() AND status = 'CONFIRMED')
  - "Admins can view all resale" → 
    SELECT if role IN ('admin', 'event_organizer')

3.3 FROM LOGIC_FLOW v1.4 §7 — FLOW SUMMARY (PSEUDOCODE ONLY)
────────────────────────────────────────────────────────────────────────────────

⚠️ FLAG #1: RESERVED state = synthetic (status='PENDING' + buyer_user_id 
   IS NOT NULL). TIDAK ADA di DB enum.

STATE DEFINITION:
  | State           | Description                                         |
  |-----------------|-----------------------------------------------------|
  | PENDING         | Tiket terdaftar, menunggu pembeli (buyer_user_id NULL) |
  | RESERVED(*)     | Buyer sudah klaim, menunggu pembayaran (3 min TTL)  |
  |                 | (*) = synthetic: status='PENDING' + buyer NOT NULL  |
  | COMPLETED       | Transaksi selesai, ownership transferred            |
  | CANCELLED       | Seller batal                                        |
  | PENDING_PAYOUT  | Buyer sudah bayar, payout gagal (retry exhausted)   |

LIST TICKET FOR RESALE — Flow:

  Function ListTicket(ctx, req):
    Step 1: SELECT ticket BY id AND owner_user_id = JWT sub
              - If not found or not owner → 403
    Step 2: Verify ticket.status = 'CONFIRMED'
              - If not → 422 UNPROCESSABLE_ENTITY
    Step 3: Check no active listing:
              - SELECT 1 FROM resale_transactions WHERE ticket_id = ticket.id 
                AND status = 'PENDING'
              - If found → 409 RESALE_LISTING_EXISTS
    Step 4: Get original_price from ticket's section:
              - SELECT price FROM sections WHERE id = ticket.section_id
    Step 5: Compute price cap:
              - cap_percent = SELECT value FROM system_config 
                              WHERE key = 'resale_price_cap_percent' (10)
              - cap_amount = original_price * (1 + cap_percent / 100)
    Step 6: Validate req.resale_price <= cap_amount
              - If exceed → 422 PRICE_EXCEEDS_CAP
    Step 7: Compute platform_fee + seller_payout:
              - fee_rate = env RESALE_PLATFORM_FEE_RATE (0.025)
              - platform_fee = resale_price * fee_rate
              - seller_payout = resale_price - platform_fee
              - Use decimal.Decimal (shopspring/decimal) — 2 decimal precision
    Step 8: INSERT resale_transactions:
              - ticket_id, event_id, seller_user_id, buyer_user_id=NULL,
                original_price, resale_price, platform_fee, seller_payout,
                status='PENDING', created_at=NOW()
    Step 9: Trigger handle_resale_lifecycle (INSERT) → tickets.status = 
            'RESALE_PENDING'
    Step 10: Return { resale_id, original_price, resale_price, platform_fee, 
                       seller_payout, status='PENDING' }

BUY RESALE TICKET (with FOR UPDATE) — Flow:

  Function BuyResaleTicket(ctx, resaleID):
    Step 1: buyer_user_id = JWT sub (from claims — IDOR patch)
              - Body is EMPTY (no buyer_user_id in request)
    Step 2: BEGIN transaction
    Step 3: SELECT resale FROM resale_transactions 
            WHERE id = resaleID FOR UPDATE
              - If not found → 404
    Step 4: Validate:
              - resale.seller_user_id != buyer_user_id (cannot buy own)
              - resale.status = 'PENDING'
              - resale.buyer_user_id IS NULL 
                (exclude reserved state — FLAG #1)
    Step 5: UPDATE resale_transactions SET:
              buyer_user_id = buyer_user_id,
              status = 'PENDING' (tetap — tidak ada RESERVED enum),
              updated_at = NOW()
            WHERE id = resaleID
    Step 6: COMMIT
    Step 7: Publish delayed message:
              queue = "resale_expiry_check"
              delay = 180 seconds
              payload = { resale_id: resaleID }
    Step 8: Return:
              {
                resale_id, 
                status: "RESERVED" (SYNTHETIC — FLAG #1 mapping), 
                reservation_expires_at: NOW() + 3 min (computed, not stored),
                payment_link: <generated via Payment Gateway>
              }

PAYMENT WEBHOOK + PAYOUT — Flow:

  Function HandleResalePaymentWebhook(webhook):
    Step 1: Validate webhook signature (reuse PaymentGateway adapter FASE 4)
    Step 2: Lookup resale_transaction BY payment_transaction_id
    Step 3: If webhook status = SUCCESS:
      a. Attempt payout to seller (retry 3x with exponential backoff):
           - Call PaymentGateway.Payout(seller_payout, seller_id)
           - If success → UPDATE status = 'COMPLETED', 
                          completed_at=NOW(), payout_transaction_id=xxx
           - If retry exhausted (3x fail) → UPDATE status = 'PENDING_PAYOUT'
                                              + INSERT admin_actions 
                                                (MANUAL_REFUND, 
                                                reason='PAYOUT_RETRY_EXHAUSTED')
    Step 4: Trigger handle_resale_lifecycle fires:
      - If COMPLETED → old ticket RESOLD + new ticket for buyer

  ⚠️ NOTE: Payout timing — apakah synchronous dalam webhook handler 
  atau async worker? Rekomendasi: async worker (via RabbitMQ) untuk avoid 
  webhook timeout. Webhook handler hanya validate + enqueue payout job.

RESALE EXPIRY WORKER — Flow:

  Function ResaleExpiryWorker():
    Ticker every 1 minute (idempotent — cek reserved rows):
      Step 1: SELECT resale_transactions WHERE status='PENDING' 
              AND buyer_user_id IS NOT NULL 
              AND created_at < NOW() - INTERVAL '3 minutes' 
              AND updated_at < NOW() - INTERVAL '3 minutes'
      Step 2: FOR EACH expired:
        a. UPDATE resale_transactions SET:
             buyer_user_id = NULL,
             updated_at = NOW()
           WHERE id = expired.id
        b. (Optional) INSERT admin_actions for audit
      Step 3: Log summary (count of resets)

  ⚠️ FLAG #1 alignment: TIDAK ada status RESERVED, TIDAK ada 
     reservation_expires_at column. TTL di-track via created_at + delayed 
     message. Worker idempotent — bisa run multiple times tanpa masalah.

CANCEL LISTING — Flow:

  Function CancelListing(ctx, resaleID):
    Step 1: BEGIN transaction
    Step 2: SELECT resale FOR UPDATE WHERE id = resaleID
    Step 3: Verify seller_user_id = JWT sub
              - If not → 403
    Step 4: Verify status = 'PENDING' AND buyer_user_id IS NULL
              - If buyer already claimed → 422 (cannot cancel)
    Step 5: UPDATE resale_transactions SET:
              status = 'CANCELLED', cancelled_at = NOW()
    Step 6: COMMIT
    Step 7: Trigger handle_resale_lifecycle (CANCELLED) → tickets.status = 
            'CONFIRMED'
    Step 8: Return { resale_id, status: 'CANCELLED', cancelled_at }

8.4 FLAG #1 — RESERVED SYNTHETIC STATE
────────────────────────────────────────────────────────────────────────────────

  Problem: DATABASE_SCHEMA resale_status_enum = {PENDING, COMPLETED, 
  CANCELLED, PENDING_PAYOUT}. Tidak ada RESERVED.

  Resolution (Opsi A):
    - Runtime "reserved" = status='PENDING' AND buyer_user_id IS NOT NULL
    - API response MAP to "RESERVED" string (synthetic)
    - TTL tracked via delayed message (RabbitMQ) + created_at column
    - Filter query: WHERE status='PENDING' AND buyer_user_id IS NULL
    - Worker: reset buyer_user_id to NULL after TTL

  Trade-off: API response slightly different dari DB state — acceptable 
  untuk preserve schema integrity (no migration amendment).

8.6 FLAG #3 — PENDING_PAYOUT TRIGGER

Latar Belakang:
  Fitur ini lahir dari inspirasi website konser Blackpink. Tujuannya adalah
  mentransformasi E-Tix Flash dari sekadar sistem CRUD tiket, menjadi SaaS
  Ticketing kelas Enterprise yang bisa menangani:
  1. Assigned Seating (Pilih kursi spesifik) - Cocok untuk Teater/Bioskop.
  2. Zoned/General Admission (Pilih area/zona) - Cocok untuk Konser/Festival.
  
  Keunikan: EO (Event Organizer) bisa meng-upload desain denah custom mereka
  sendiri (atau kita percantik via AI) dan menempelkannya di web. User bisa 
  mengklik area di gambar untuk melihat POV, Jarak, dan memilih tiket.

SECTION 1 — SCOPE & OBJECTIVES
================================================================================

1.1 SCOPE — IN
────────────────────────────────────────────────────────────────────────────────
✅ Database & Model:
   - Kolom `seating_mode` (ZONED | ASSIGNED) di tabel events.
   - Kolom `layout_image_url` (URL gambar denah) di tabel events.
   - Kolom `layout_zones` (JSONB) untuk menyimpan koordinat poligon SVG.

✅ Backend Logic (Dual-Mode):
   - Mode ZONED: Menggunakan **Redis DECR** (Atomic Counter) untuk memotong 
     kuota zona. BUKAN Bitmask.
   - Mode ASSIGNED: Tetap menggunakan **Redis Bitmask + Lua Script** (FASE 3).
   - Worker Batch Insertion: Menggunakan `pgx.CopyFrom` untuk insert massal 
     data tiket (menghindari bottleneck saat 20.000 RPS).
   - Random Seat Assignment: Generate `seat_position` (NULL di awal) secara 
     acak saat tiket dicetak/di-scan.

✅ Frontend (Next.js 15):
   - Menggunakan SVG Overlay + Image 2D. 
   - Responsive: `hidden md:block` (Map di Desktop) & `block md:hidden` (List di Mobile).
   - UI Beradaptasi: 
     * ZONED -> Tampilkan Progress Bar (Sisa Kuota).
     * ASSIGNED -> Tampilkan Grid Kursi.
   - Efek Visual: Dark mode, Glassmorphism (backdrop-blur), transisi mulus.

✅ Tooling (Zero Budget):
   - Menggunakan **Figma** untuk menggambar koordinat poligon (export ke SVG/JSON).
   - Tidak membuat In-App Editor (terlalu kompleks).

1.2 SCOPE — OUT
────────────────────────────────────────────────────────────────────────────────
❌ In-App Zone Editor (Drag-and-drop poligon di dashboard EO).
❌ WebGL / Three.js (3D Rendering).
❌ Integrasi AI (Stitch) secara live di dalam aplikasi.
❌ WebSocket (Cukup pakai polling di frontend).

SECTION 3 — ACCEPTANCE CRITERIA
================================================================================

✅ Migrasi database sukses dan sesuai dengan skema.
✅ Mode ZONED: Bisa memotong kuota tanpa race condition (Redis DECR).
✅ Mode ASSIGNED: Tetap pakai Bitmask (zero regression).
✅ Worker Batch: Bisa insert 1000 tiket < 1 detik menggunakan pgx.CopyFrom.
✅ Frontend: Map interaktif jalan di Desktop, List rapi di Mobile.
✅ UI "Mahal": Dark mode, glassmorphism, transisi halus.
✅ CI Hijau: Lint, Unit, Security, Integration, Frontend Build semuanya PASS.

================================================================================
SECTION 4 — RISKS & MITIGATIONS
================================================================================

| Risk | Mitigation |
|---|---|
| Editor Map Terlalu Rumit | Gunakan Figma. Backend cuma terima JSON string. |
| Mobile UI Berantakan | Pakai Tailwind `hidden md:block`. List fallback di mobile. |
| DB Bottleneck saat Insert | Wajib pakai `pgx.CopyFrom` dan Batching (Jangan looping insert). |
| Responsive SVG Meleset | Gunakan `viewBox` pada SVG, jangan koordinat pixel hardcoded. |

================================================================================
SECTION 5 — NOTED PRINCIPLES (From Gemini & DeepSeek)
================================================================================

1. "Keep It Simple, Stupid (KISS)": Jangan bikin Strategy Pattern yang kompleks. 
   Cukup satu tabel `bookings`, kasih flag `seating_mode`. Pakai if-else biasa.
2. "Lazy Generation": Untuk ZONED, jangan generate nomor kursi saat checkout.
   Generate saat tiket di-print/di-scan untuk mengurangi beban DB saat war tiket.
3. "No WebGL": SVG + Tailwind udah cukup bikin UI terlihat seperti Blackpink.
